Setup Completo

Instalacao e Licenca

Tudo que voce precisa pra colocar o resource no ar. A licenca (key) faz parte da instalacao, entao esta tudo junto aqui.

1. Extrair o resource

Coloque a pasta MathStoreFairyWing-V7 dentro da sua pasta resources/.

Nome da pastaO nome da pasta precisa ser exatamente MathStoreFairyWing-V7. Keybinds, eventos internos e state bags dependem desse nome.

2. Configurar a Key (Convar)

Cada servidor precisa de uma key unica para o resource funcionar. Essa key e configurada como uma convar no seu server.cfg, e deve vir antes do ensure.

server.cfg
## ─── MathStore Fairy Wing V7 ───

# 1. Defina a key (ANTES do ensure)
set mathstore_key_fairyv7 "AP-XXXX-XXXX-XXXX"

# 2. Inicie o resource
ensure MathStoreFairyWing-V7
Cuidado com a keyNao compartilhe sua key. Cada key e vinculada ao IP do servidor. Se mudar de host, entre em contato para migrar.

3. Dependencias

ResourceStatusFuncao
ox_libOpcionalComandos com sugestoes, notificacoes estilizadas. Ativa em Config.UseOxLib
qb-core / qbx_coreAuto-detectadoBridge QB/QBX para permissoes e player data
es_extendedAuto-detectadoBridge ESX para permissoes e player data
vrpAuto-detectadoBridge vRP para grupos, permissoes e identidade
Modo StandaloneSe nenhum framework for detectado, o resource roda sozinho. Tudo funciona, apenas sem integracao de permissoes nativas do framework.
Configuracao

Config.lua

O arquivo config/config.lua centraliza todas as opcoes do resource. Tudo que voce pode mudar esta aqui.

Framework e Geral

config.lua
-- Deteccao automatica do framework
Config.Framework = 'auto'     -- 'auto' | 'qbx' | 'qb' | 'esx' | 'vrp' | 'standalone'

-- Usar ox_lib para comandos e notificacoes
Config.UseOxLib = true

-- Idioma do sistema (notificacoes, keybinds, HUD)
Config.Locale = 'pt-BR'      -- 'pt-BR' | 'en-US' | 'es' | 'fr' | 'pt-PT' | 'th'
DicaCom Config.Framework = 'auto', o resource detecta sozinho qual framework esta rodando. So force manualmente se tiver algum conflito.

Notificacoes

config.lua
Config.Notifications = {
    type     = 'auto',    -- 'auto' | 'ox_lib' | 'qb' | 'esx' | 'vrp' | 'native'
    duration = 5000,     -- Duracao em milissegundos
}
ValorComportamento
'auto'Detecta: ox_lib > framework > native (nessa ordem)
'ox_lib'Forca ox_lib:notify
'qb'Forca QBCore notification
'esx'Forca ESX.ShowNotification
'vrp'Forca vRP notification
'native'Notificacao nativa do GTA V

Keybinds

config.lua
Config.Keybinds = {
    toggle = '',      -- Abrir/fechar asas (vazio = sem tecla padrao)

Multi-Framework

Sistema Bridge

O resource detecta automaticamente o framework do servidor e adapta todas as funcoes internas. Voce nao precisa configurar nada na maioria dos casos.

Como a deteccao funciona

Em bridge/shared.lua, o sistema verifica quais resources estao rodando e escolhe o bridge correto:

FrameworkResource DetectadoResultado
QBX (Qbox)qbx_core'qbx'
QB-Coreqb-core'qb'
ESXes_extended'esx'
vRPvrp'vrp'
Nenhum-'standalone'

Funcoes do Bridge (Server-side)

Funcoes disponiveis no server para interagir com os dados do jogador:

server
-- Obter o objeto do jogador no framework
local player = Bridge.GetPlayer(source)

-- Obter identificador unico (citizenid, identifier, user_id)
local cid = Bridge.GetCitizenId(source)

-- Nome do personagem no framework
local name = Bridge.GetPlayerName(source)

-- Job atual (nome + grade)
local job = Bridge.GetJob(source)

-- Checar permissao (sistema multi-layer)
local allowed = Bridge.HasPermission(source, 'use')

-- Enviar notificacao (adapta ao framework detectado)
Bridge.Notify(source, 'Mensagem', 'success')

-- Executar callback definido no config
Bridge.ExecuteCallback('CanEquipWings', source, cor)

Funcoes do Bridge (Client-side)

Funcoes disponiveis no client:

client
-- Dados do jogador no framework
local data = Bridge.GetPlayerData()

-- Jogador ja terminou de carregar?
local loaded = Bridge.IsPlayerLoaded()

-- Notificacao client-side
Bridge.ShowNotification('Texto', 'info', 5000)

-- ox_lib esta disponivel no servidor?
local has = Bridge.HasOxLib()
Controle de Acesso

Sistema de Permissoes

Controla quem pode usar cada funcionalidade do resource. O sistema possui 8 camadas de checagem, verificadas em ordem. Quando qualquer camada da uma resposta definitiva (permitir ou negar), as proximas nao sao verificadas.

Chaves de Permissao

Existem duas chaves usadas em todo o sistema:

ChaveOnde e usadaDescricao
'use'Todos os comandos de asas, HUD, animacoesPermissao geral para usar o resource
'admin_cleanup'/asaslimpar7Permissao admin para limpar todas as asas do servidor

Fluxo completo de checagem (8 camadas)

Quando um jogador executa qualquer comando, a permissao e verificada nessa ordem:

1. Config.Callbacks.HasPermission(source, permission) → Retorna true/false? Usa e para aqui → Retorna nil? Continua pra proxima camada 2. ACE Permission: IsPlayerAceAllowed(source, Permissions.Ace[perm]) → Ex: 'MathStoreFairyWing-V7.use' (gerado automaticamente) 3. Feature Config: Permissions.Features[perm].enabled → Se enabled = false, TODOS tem acesso (sem restricao) 4. CitizenID: Permissions.Features[perm].citizenids → Lista de IDs especificos permitidos 5. vRP Groups: Permissions.VRP[perm] → Ex: {'Fada', 'Admin'} 6. Sets (QBX): Permissions.Features[perm].sets 7. ACE Groups: Permissions.Groups[grupo] → Verifica group.admin, group.vip, etc. 8. Jobs: Permissions.Features[perm].jobs → Ex: {'police', 'ambulance'}

Permitir para todos (sem nenhuma restricao)

permissions.lua
Permissions.Features = {
    use = {
        enabled = false,    -- false = TODOS podem usar, sem checagem
    },
}

Restringir por grupo vRP

permissions.lua
Permissions.VRP = {
    use = { 'Fada', 'Admin' },            -- Nomes exatos dos grupos vRP
    admin_cleanup = { 'Admin' },
}

Restringir por ACE Permission

O resource gera os nomes ACE automaticamente usando GetCurrentResourceName(). Ou seja, se a pasta e MathStoreFairyWing-V7, os ACEs ficam:

permissions.lua
Permissions.Ace = {
    use = GetCurrentResourceName() .. '.use',             -- 'MathStoreFairyWing-V7.use'
    admin_cleanup = GetCurrentResourceName() .. '.admin',  -- 'MathStoreFairyWing-V7.admin'
}
server.cfg
# Liberar uso pra grupo VIP
add_ace group.vip MathStoreFairyWing-V7.use allow

# Liberar admin cleanup
add_ace group.admin MathStoreFairyWing-V7.admin allow

Restringir por Job (QB/ESX)

permissions.lua
Permissions.Features = {
    use = {
        enabled = true,
        jobs = { 'police', 'ambulance' },   -- Nome do job no framework
    },
}

Restringir por CitizenID especifico

permissions.lua
Permissions.Features = {
    use = {
        enabled = true,
        citizenids = { 'ABC12345', 'XYZ67890' },
    },
}

Grupos ACE customizados

Mapeia nomes amigaveis para os ACE groups reais do seu servidor:

permissions.lua

Callbacks

Callbacks: Injetando Logica do Seu Servidor

Os callbacks permitem que voce escreva sua propria logica dentro do fluxo do resource, sem editar nenhum arquivo interno. Tudo fica em config/config.lua. Use eles para decidir quem pode usar, o que acontece quando equipa, o que acontece quando remove, e qualquer regra personalizada do seu servidor.

Tabela de Callbacks

CallbackParametrosRetornoMomento da chamada
CanOpenHUDsourcetrue/falseAntes de abrir a HUD radial
CanEquipWingssource, cortrue/falseAntes de equipar asas
OnWingsEquippedsource, cornenhumDepois de equipar asas
OnWingsRemovedsourcenenhumDepois de remover asas
HasPermissionsource, permissiontrue/false/nilAntes de qualquer checagem de permissao
Sobre o CanEquipWingsO parametro cor pode ser nil ou um number. Quando e nil, o server esta checando se o botao "Pegar Asa" da HUD deve ficar habilitado. Quando e um numero, e uma tentativa real de equipar. Trate os dois casos no seu callback.

Cenarios com exemplos completos

Cada cenario abaixo e completo e auto-contido. Copie o que fizer sentido pro seu servidor.

Exigir item no inventario pra equipar (e devolver ao remover) ESX

O jogador precisa ter o item fairy_essence no inventario. Ao equipar, o item e consumido. Ao remover as asas, o item volta pro inventario.

config.lua
Config.Callbacks = {
    CanEquipWings = function(source, cor)
        if cor then
            -- Tentativa real de equipar: checar item
            local xPlayer = ESX.GetPlayerFromId(source)
            local item = xPlayer.getInventoryItem('fairy_essence')
            if not item or item.count < 1 then
                Bridge.Notify(source, 'Voce precisa de Essencia de Fada!', 'error')
                return false
            end
            return true
        end
        -- cor = nil: apenas checando se a HUD mostra o botao
        return true
    end,

    OnWingsEquipped = function(source, cor)
        -- Remover item do inventario apos equipar
        local xPlayer = ESX.GetPlayerFromId(source)
        xPlayer.removeInventoryItem('fairy_essence', 1)
    end,

    OnWingsRemoved = function(source)
        -- Devolver item ao remover
        local xPlayer = ESX.GetPlayerFromId(source)
        xPlayer.addInventoryItem('fairy_essence', 1)
    end,
}
Exigir item no inventario pra equipar (e devolver ao remover) QB-Core

Mesma logica do ESX, mas usando as funcoes do QB-Core.

        Player.Functions.RemoveItem('fairy_essence', 1)
    end,

    OnWingsRemoved = function(source)
        local Player = QBCore.Functions.GetPlayer(source)
        Player.Functions.AddItem('fairy_essence', 1)
    end,

Exigir item no inventario pra equipar (e devolver ao remover) vRP

Mesma logica usando funcoes do vRP.

config.lua
Config.Callbacks = {
    CanEquipWings = function(source, cor)
        if cor then
            local user_id = vRP.getUserId(source)
            if not user_id then return false end
            local amount = vRP.getInventoryItemAmount(user_id, 'essencia_fada')
            if amount < 1 then
                vRP.sendServiceNotif(source, 'Voce precisa de Essencia de Fada!')
                return false
            end
            return true
        end
        return true
    end,

    OnWingsEquipped = function(source, cor)
        local user_id = vRP.getUserId(source)
        vRP.tryGetInventoryItem(user_id, 'essencia_fada', 1)
    end,

    OnWingsRemoved = function(source)
        local user_id = vRP.getUserId(source)
        vRP.tryGiveInventoryItem(user_id, 'essencia_fada', 1)
    end,
}
Jogador precisa estar em um local especifico Qualquer Framework

O jogador so pode equipar se estiver dentro de uma area definida. Util pra criar "templos", altares ou zonas magicas onde as asas sao liberadas.

config.lua
-- Area permitida (coordenadas centrais + raio)
local ZONA_ALTAR = { x = -1042.5, y = -2745.3, z = 13.9, raio = 15.0 }

Config.Callbacks = {
    CanEquipWings = function(source, cor)
        if cor then
            -- Pegar a posicao atual do jogador
            local ped = GetPlayerPed(source)
            local coords = GetEntityCoords(ped)

            -- Calcular distancia ate o altar
            local dx = coords.x - ZONA_ALTAR.x
            local dy = coords.y - ZONA_ALTAR.y
            local dz = coords.z - ZONA_ALTAR.z
            local dist = math.sqrt(dx*dx + dy*dy + dz*dz)

            if dist > ZONA_ALTAR.raio then
                Bridge.Notify(source, 'Voce precisa estar no Altar das Fadas!', 'error')
                return false
            end
        end
        return true
    end,
}
Jogador precisa ter completado uma quest ou progressao Qualquer Framework

Se o seu servidor tem sistema de quests ou progressao, voce pode verificar se o jogador completou uma etapa antes de liberar as asas. Este exemplo usa exports de um resource de quests generico, adapte pro sistema do seu servidor.

config.lua
Config.Callbacks = {
    CanEquipWings = function(source, cor)
        if cor then
            -- Exemplo generico: chamar export do resource de quest
            local completed = exports['meu_quest_system']:isQuestComplete(source, 'fairy_quest_01')
            if not completed then
                Bridge.Notify(source, 'Complete a quest "O Despertar da Fada" primeiro!', 'error')
                return false
            end
        end
        return true
    end,

    OnWingsEquipped = function(source, cor)
        -- Registrar no sistema de progressao que desbloqueou
        exports['meu_quest_system']:addProgress(source, 'fairy_mastery', 10)
    end,
}

Asas somente para VIPs (ou qualquer ACE group) Qualquer Framework

Bloquear tanto a HUD quanto o equipar para quem nao e VIP. Pode usar com qualquer grupo ACE do seu servidor.

config.lua
Config.Callbacks = {
    HasPermission = function(source, permission)
        if permission == 'use' then
            return IsPlayerAceAllowed(source, 'group.vip')
        end
        return nil  -- Outras permissoes: usar sistema padrao
    end,

    CanOpenHUD = function(source)
        if not IsPlayerAceAllowed(source, 'group.vip') then

            return false
        end
        return true
    end,
}
Combinar varias regras: item + local + nivel ESX

Exemplo completo combinando varias condicoes. O jogador precisa ter um item, estar num local especifico e ter nivel minimo. Mostra como compor regras complexas num unico callback.

config.lua
local ALTAR = { x = -1042.5, y = -2745.3, z = 13.9, raio = 15.0 }

Config.Callbacks = {
    CanEquipWings = function(source, cor)
        if not cor then return true end  -- HUD check: permitir visual

        -- Regra 1: Precisa do item
        local xPlayer = ESX.GetPlayerFromId(source)
        local item = xPlayer.getInventoryItem('fairy_essence')
        if not item or item.count < 1 then
            Bridge.Notify(source, 'Voce precisa de Essencia de Fada!', 'error')
            return false
        end

        -- Regra 2: Precisa estar no altar
        local ped = GetPlayerPed(source)
        local c = GetEntityCoords(ped)
        local dist = #(vector3(c.x, c.y, c.z) - vector3(ALTAR.x, ALTAR.y, ALTAR.z))
        if dist > ALTAR.raio then
            Bridge.Notify(source, 'Va ate o Altar das Fadas!', 'error')
            return false
        end

        -- Regra 3: Nivel minimo (export do seu sistema)
        local level = exports['meu_level_system']:getLevel(source)
        if level < 30 then
            Bridge.Notify(source, 'Voce precisa ser nivel 30!', 'error')
            return false
        end

        return true
    end,

    OnWingsEquipped = function(source, cor)
        local xPlayer = ESX.GetPlayerFromId(source)
        xPlayer.removeInventoryItem('fairy_essence', 1)
        exports['meu_level_system']:addXP(source, 50)
    end,
}
Override total da permissao com logica propria Qualquer Framework

Se voce tem um sistema de permissao proprio no servidor e quer ignorar completamente o sistema de 8 camadas, use o callback HasPermission. Retornar true ou false pula todas as checagens padrao. Retornar nil deixa o sistema continuar normalmente.

config.lua
Config.Callbacks = {
    HasPermission = function(source, permission)
        if permission == 'use' then
            -- Usar seu proprio sistema de permissao
            return exports['meu_perm_system']:hasPermission(source, 'fairy_wings')
        end

        if permission == 'admin_cleanup' then
            return IsPlayerAceAllowed(source, 'group.admin')
        end

        return nil  -- Para qualquer permissao desconhecida, usar padrao
    end,
}
Permissao baseada em cargos do Discord Qualquer Framework

Vamos supor que voce quer basear seu sistema de permissao em cargos do Discord. Isso e possivel! Basta ter um resource de integracao Discord no servidor (como badger_discord_api, discord_perms, deek_discord, etc.) que forneca um export pra checar cargo. O callback HasPermission faz o resto.

config.lua
Config.Callbacks = {
    HasPermission = function(source, permission)
        if permission == 'use' then
            -- ID do cargo "Fada" no Discord (clique direito no cargo > Copiar ID)
            local hasCargo = exports['badger_discord_api']:isRolePresent(source, 1234567890123456)
            return hasCargo  -- true = tem cargo, false = nao tem
        end

        if permission == 'admin_cleanup' then
            -- ID do cargo "Admin" no Discord
            return exports['badger_discord_api']:isRolePresent(source, 9876543210987654)
        end

        return nil  -- outras permissoes: usar sistema padrao
    end,
}
Combinando Discord + sistema padraoSe voce quiser que o jogador tenha acesso se tiver o cargo do Discord OU se passar no sistema padrao (vRP, ACE, job, etc.), basta retornar nil quando o cargo nao for encontrado. Assim o sistema continua checando as outras 7 camadas normalmente:
config.lua
Config.Callbacks = {
    HasPermission = function(source, permission)
        if permission == 'use' then
            local discordOk = exports['badger_discord_api']:isRolePresent(source, 1234567890123456)
            if discordOk then return true end
            return nil  -- nao tem cargo Discord? deixa o sistema padrao checar vRP/ACE/etc
        end
        return nil
    end,
}
Eventos e Integracao

Eventos: Escutando e Integrando

O resource dispara diversos eventos ao longo do ciclo de vida das asas. Voce pode escutar esses eventos de outros resources pra criar integracoes, sincronizar sistemas, ou reagir quando algo acontece.

Nomenclatura dos eventos

Todos os eventos sao prefixados automaticamente com o nome do resource para evitar conflito. O prefixo segue o padrao:

lua
-- Formato: NomeDoResource:tipo:acao
-- Exemplo:
'MathStoreFairyWing-V7:spawn'          -- Comando (server → client)
'MathStoreFairyWing-V7:sync:spawned'   -- Sincronizacao (client → server)
'MathStoreFairyWing-V7:sync:spawn'     -- Broadcast (server → outros clients)
Sobre os nomesOs nomes exatos sao gerados automaticamente em bridge/shared.lua usando GetCurrentResourceName(). Abaixo, usamos o nome padrao MathStoreFairyWing-V7.

Eventos Client → Server (Sincronizacao)

Quando o jogador faz algo localmente, o client envia esses eventos pro server pra que outros jogadores vejam:

EventoParametrosQuando e enviado

MathStoreFairyWing-V7:sync:animChangedanimKeyAnimacao da asa mudou
MathStoreFairyWing-V7:sync:removed-Asas removidas localmente
MathStoreFairyWing-V7:sync:requestBulk-Jogador pede estado atual (ao conectar)

Quando um comando e validado no server (permissoes + callbacks), o server envia pro client executar. Estes sao direcionados ao jogador que executou o comando:

Cenarios de integracao com exemplos completos

Cada cenario abaixo mostra como escutar ou reagir a eventos do resource a partir de outro resource do seu servidor.

Reagir quando um jogador comeca ou para de voar Client - Outro Resource

Seu resource de HUD ou sistema de status pode escutar o inicio/fim do voo pra mostrar um indicador, aplicar efeito, ou alterar a camera.

client.lua (outro resource)
-- Jogador comecou a voar
AddEventHandler('flight:start', function(playerId)
    print('[MeuHUD] Player voando: ' .. playerId)
    -- Ativar indicador de voo na HUD
    SendNUIMessage({ action = 'showFlightIndicator', active = true })
end)

-- Jogador parou de voar
AddEventHandler('flight:end', function(playerId)
    print('[MeuHUD] Player aterrisou: ' .. playerId)
    SendNUIMessage({ action = 'showFlightIndicator', active = false })
end)

-- Animacao de voo mudou (ex: planando, batendo asas, descendo)
AddEventHandler('flight:animationChange', function(playerId, state)
    print('[MeuHUD] Animacao voo: ' .. state)
end)
Detectar modo de voo especifico (rasante, subida) Client - Outro Resource

Se voce quer aplicar efeitos visuais diferentes conforme o tipo de manobra que o jogador faz no ar.

client.lua (outro resource)
-- Modo rasante (voo baixo rapido)
AddEventHandler('wing:rasanteActive', function(active)
    if active then
        -- Aplicar efeito de velocidade, motion blur, etc.
        SetTimecycleModifier('spectator5')
    else
        ClearTimecycleModifier()
    end
end)

-- Modo subida (ganhando altitude)
AddEventHandler('wing:subidaActive', function(active)
    if active then
        -- Particulas de vento, trail, etc.
    end
end)
Escutar no server quando alguem equipa/remove asas Server - Outro Resource

A partir de outro resource no server, voce pode escutar os eventos de sync pra logar, dar recompensa, notificar Discord, etc.

server.lua (outro resource)
-- Escutar quando alguem equipou asas
RegisterNetEvent('MathStoreFairyWing-V7:sync:spawned')
AddEventHandler('MathStoreFairyWing-V7:sync:spawned', function(cor, initialState)
    local src = source
    print('[Log] Player ' .. src .. ' equipou asas cor ' .. cor)

    -- Exemplo: enviar pro Discord
    exports['discord_log']:sendLog('wings', 
        GetPlayerName(src) .. ' equipou asas (cor ' .. cor .. ')'
    )
end)

-- Escutar quando alguem removeu asas
RegisterNetEvent('MathStoreFairyWing-V7:sync:removed')
AddEventHandler('MathStoreFairyWing-V7:sync:removed', function()
    local src = source
    print('[Log] Player ' .. src .. ' removeu asas')
end)
Sobre escutar net eventsQuando voce registra um RegisterNetEvent de outro resource, voce esta escutando o mesmo evento que o Fairy Wing V7 ja escuta internamente. O FiveM permite multiplos handlers. Sua logica roda junto, sem interferir no resource original.
Reagir a mudancas de animacao de outro jogador Client - Outro Resource

Quando outro jogador troca de animacao (ex: abre asas), o broadcast chega no seu client. Voce pode usar pra criar efeitos visuais sincronizados.

client.lua (outro resource)
RegisterNetEvent('MathStoreFairyWing-V7:sync:anim')
AddEventHandler('MathStoreFairyWing-V7:sync:anim', function(serverId, animKey)
    print('[Sync] Player ' .. serverId .. ' trocou animacao pra: ' .. animKey)

    -- Exemplo: Criar particulas ao redor quando alguem abre asas
    if animKey == 'open' or animKey == 'bater' then
        local ped = GetPlayerPed(GetPlayerFromServerId(serverId))
        if ped and ped ~= 0 then
            -- Adicionar particula no ped
        end
    end
end)

Disparando eventos do Fairy Wing V7 a partir de outro resource

Os cenarios acima mostram como escutar eventos. Mas voce tambem pode disparar eventos do Fairy Wing V7 direto do seu resource, sem depender de comandos. Isso e util quando o fluxo comeca fora do Fairy Wing V7 (loja, item, NPC, quest, etc.).

ImportanteQuando voce dispara o evento direto, voce pula o sistema de permissoes e callbacks do Fairy Wing V7. A responsabilidade de checar se o jogador pode ou nao usar fica no SEU resource. Use isso so quando voce quer controle total do fluxo.
Loja ou NPC que da asas ao jogador ao comprar Server - Outro Resource

O jogador interage com um NPC ou loja, paga, e recebe as asas direto. Do server do seu resource, voce manda o evento :spawn pro client do jogador.

server.lua (outro resource - ex: loja)
-- Jogador comprou asas na loja, cor 5
RegisterNetEvent('minhaLoja:comprarAsas')
AddEventHandler('minhaLoja:comprarAsas', function(cor)
    local src = source

    -- Sua logica de pagamento
    local xPlayer = ESX.GetPlayerFromId(src)
    if xPlayer.getMoney() < 5000 then
        TriggerClientEvent('esx:showNotification', src, 'Dinheiro insuficiente!')
        return
    end
    xPlayer.removeMoney(5000)

    -- Dar as asas pro jogador (dispara direto no Fairy Wing V7)
    TriggerClientEvent('MathStoreFairyWing-V7:spawn', src, cor)
end)
Item usavel que equipa asas ao usar ESX

Voce registra um item usavel no server. Quando o jogador usa o item, as asas sao equipadas automaticamente e o item e consumido.

server.lua (outro resource - ex: items)
-- Registrar item usavel 'asas_de_fada'
ESX.RegisterUsableItem('asas_de_fada', function(source)
    local src = source
    local xPlayer = ESX.GetPlayerFromId(src)

    -- Consumir o item
    xPlayer.removeInventoryItem('asas_de_fada', 1)

    -- Equipar asas cor 1
    TriggerClientEvent('MathStoreFairyWing-V7:spawn', src, 1)
end)
Item usavel que equipa asas ao usar QB-Core

Mesma logica do ESX, mas usando QB-Core.

server.lua (outro resource - ex: items)
-- Registrar item usavel 'asas_de_fada'
QBCore.Functions.CreateUseableItem('asas_de_fada', function(source)

    local Player = QBCore.Functions.GetPlayer(src)

    -- Consumir o item
    Player.Functions.RemoveItem('asas_de_fada', 1)

    -- Equipar asas cor 1

end)
Remover asas de um jogador a partir de outro resource Server - Outro Resource

Se o jogador morreu, foi preso, entrou em uma zona restrita, ou qualquer outra condicao do seu servidor, voce pode forcar a remocao das asas.

AddEventHandler('esx:onPlayerDeath', function(data)
    local src = source

Trocar a cor das asas de outro resource Server - Outro Resource

O jogador ja tem asas equipadas e voce quer mudar a cor sem remover e re-equipar. Util pra sistema de evolucao, recompensas, ou loja de cosmeticos.

Ativar/desativar voo ou abrir HUD de outro resource Server - Outro Resource

Voce pode controlar qualquer funcionalidade do Fairy Wing V7 remotamente. Exemplos com varios eventos uteis:

server.lua (outro resource)

Fluxo completo: do comando ate a sincronizacao

Pra entender como tudo se conecta, aqui esta o fluxo completo de quando um jogador digita /asas7 5:

Jogador: /asas7 5 ↓ Server: Recebe comando registrado ↓ Bridge.HasPermission(source, 'use') → Checagem de 8 camadas (ver secao Permissoes) ↓ SEM permissao? → Bridge.Notify() + STOP ↓ Bridge.ExecuteCallback('CanEquipWings', source, 5) → Roda o callback do seu config.lua ↓ Callback retornou false? → STOP ↓ TriggerClientEvent(':spawn', source, 5) ↓ Client: Cria a entidade da asa, aplica cor 5 ↓ TriggerServerEvent(':sync:spawned', 5, 'idle') ↓ Server: Salva em activeWings[source] Bridge.ExecuteCallback('OnWingsEquipped', source, 5) ↓ broadcastBucket(':sync:spawn', bucket, source, src, 5, 'idle') ↓ Outros jogadores no mesmo bucket veem as asas aparecerem

Routing Buckets, StateBag e Estado Interno

Informacoes avancadas sobre como o resource gerencia sincronizacao, conflitos multi-resource e estado interno.

Routing Buckets

O resource respeita routing buckets do FiveM. Jogadores em buckets diferentes nao veem as asas uns dos outros. Toda a sincronizacao e filtrada por bucket.

server (interno)
-- Cada jogador com asas tem seu bucket rastreado
activeWings[serverId] = {
    cor    = 5,
    state  = 'idle',
    bucket = 0,
}

-- Broadcasts so enviam pra jogadores no mesmo bucket
broadcastBucket(eventName, bucket, excludeSource, ...)

-- Quando o bucket muda (verificado a cada 2s):
-- Jogador muda bucket 0 → bucket 5
--   Players no bucket 0: recebem :sync:remove
--   Players no bucket 5: recebem :sync:spawn + estado
Na praticaSe voce usa apartamentos, instancias, ou qualquer sistema baseado em routing buckets (ex: qb-apartments, esx_property), as asas funcionam corretamente em cada instancia sem interferir nas outras.

StateBag (Multi-Resource)

Se o servidor possui multiplos resources de asas da MathStore (ex: DragonWings + DemonWings), o sistema usa StateBag pra evitar conflitos. Apenas um resource pode ter asas ativas por jogador.

lua
-- Chave usada no state bag
WING_STATE_KEY = 'activeWingResource'

-- Ao equipar asas, o server define:
Player(src).state:set(WING_STATE_KEY, RES_NAME, true)

-- Se outro resource de asas tentar equipar no mesmo jogador:
-- Verifica se ja existe um resource ativo
-- Se existir, pode auto-remover o anterior

-- O client escuta mudancas via:
AddStateBagChangeHandler(WING_STATE_KEY, ...)

Estado interno do Server

O server mantém tabelas de estado que rastreiam tudo que esta ativo. Util pra entender debug e comportamento:

server (interno)
-- 1. Asas ativas (indexado por server ID)
activeWings[serverId] = {
    cor    = 5,
    state  = 'idle',
    bucket = 0,
}

-- Tudo e limpo automaticamente quando o jogador desconecta
